# 成都文旅后端「wenlv-backend」实施方案

> 配套前端:`wenlv/wennv/wenlv`(Vue3 + Vite + TS)
> 定位:将前端从"离线纯演示"升级为"可运营的真实应用"。

---

## 0. 技术选型(已确认)

| 项 | 选型 | 说明 |
|---|---|---|
| 语言/框架 | Go + Gin | 标准 Gin 分层结构 |
| ORM | GORM | 自动建表迁移 |
| 业务库 | MySQL | `users` / `scenic_spots` / `foods` / `routes` / 用户资产 |
| 缓存/会话 | Redis | 登录态、热门榜单、缓存 |
| 鉴权 | JWT(golang-jwt) | 无状态 Token + Redis 黑名单 |
| 图片 | OSS 直传 | 签名 URL 直传 + 回调鉴权 |
| 配置 | godotenv / viper | 环境变量读取 |
| 中间件 | CORS / Logger / Recovery / Auth | gin-contrib 生态 |

---

## 1. 整体架构

```
浏览器 (前端 Vue3/TS)
   │  HTTP/JSON (+ JWT 鉴权)
   ▼
Gin 服务 (houduan/)
   ├── config/          读取配置 (env)
   ├── router/          路由注册 + 中间件挂载
   ├── middleware/      Auth、CORS、Logger、Recovery
   ├── handler/         HTTP 层:解析入参、校验、拼响应
   ├── service/         业务逻辑层
   ├── repository/      数据访问层 (MySQL)
   ├── model/           GORM 实体
   ├── database/        MySQL / Redis 连接、自动迁移
   ├── pkg/             jwt、oss、响应封装、哈希工具
   └── main.go          入口
   │
数据: MySQL(业务) ─ Redis(会话/缓存/榜单) ─ OSS(图片)
```

## 2. 数据库表设计(MySQL)

### 2.1 账号与内容

| 表 | 关键字段 | 说明 |
|---|---|---|
| `users` | id, username(唯一), password_hash, avatar_url, created_at, updated_at | 账号 |
| `scenic_spots` | id, name_zh, name_en, district, tags, score, lat, lng, desc, images, created_at | 景点 |
| `foods` | id, name_zh, name_en, district, tags, desc, images, created_at | 美食 |
| `routes` | id, title_zh, title_en, theme, stops, duration, difficulty, created_at | 精品路线 |

### 2.2 用户资产

| 表 | 关键字段 | 说明 |
|---|---|---|
| `favorites` | id, user_id, target_type(scenic/food/route), target_id, created_at | 收藏(联合唯一) |
| `check_ins` | id, user_id, scenic_id, photo_url, comment, visited_at, created_at | 打卡(含图片) |
| `photos` | id, user_id, target_type, target_id, url, created_at | 图墙(P2) |

### 2.3 互动 (P2)

| 表 | 关键字段 | 说明 |
|---|---|---|
| `reviews` | id, user_id, target_type, target_id, content, rating, created_at | 评价 |
| `articles` | id, user_id, title, content, cover_url, created_at | 游记 |

### 2.4 索引建议
- `favorites(user_id, target_type, target_id)` 联合唯一
- `check_ins(user_id, scenic_id)` 联合唯一
- `scenic_spots(district)`, `scenic_spots(name_zh)`

## 3. API 设计

### 3.1 认证 `/api/auth`
| 方法 | 路径 | 说明 | 鉴权 |
|---|---|---|---|
| POST | `/api/auth/register` | 注册 | — |
| POST | `/api/auth/login` | 登录,返回 JWT | — |
| POST | `/api/auth/logout` | 登出,Token 入黑名单 | ✔ |
| GET | `/api/auth/me` | 当前用户信息 | ✔ |

### 3.2 内容(替代前端静态数据)
| 方法 | 路径 | 说明 | 鉴权 |
|---|---|---|---|
| GET | `/api/scenic` | 列表:区/标签/关键词/分页 | — |
| GET | `/api/scenic/:id` | 详情 | — |
| GET | `/api/food` | 美食列表 | — |
| GET | `/api/routes` | 路线列表 | — |

### 3.3 用户资产
| 方法 | 路径 | 说明 | 鉴权 |
|---|---|---|---|
| GET | `/api/favorites` | 我的收藏 | ✔ |
| POST | `/api/favorites` | 添加收藏 | ✔ |
| DELETE | `/api/favorites/:targetType/:targetId` | 取消收藏 | ✔ |
| POST | `/api/check-ins` | 打卡 | ✔ |
| GET | `/api/check-ins` | 我的打卡列表 | ✔ |

### 3.4 图片(OSS)
| 方法 | 路径 | 说明 | 鉴权 |
|---|---|---|---|
| POST | `/api/upload/policy` | 获取 OSS 直传签名 | ✔ |

### 3.5 统一响应格式
```json
{ "code": 0, "message": "ok", "data": {} }
```
- `code=0` 成功;非 0 为业务错误码
- 鉴权失败统一 `401`;参数/逻辑错误 `400`/`404`/`422`

## 6. 里程碑

| 里程碑 | 内容 | 验收 |
|---|---|---|
| **M1 骨架** | Gin 分层目录 + MySQL/Redis 连接 + 自动迁移 + CORS/Logger | `go run` 启动,两端连通 |
| **M2 认证** | 注册/登录/JWT/登出/me + 密码哈希 | curl 可完成登录闭环 |
| **M3 内容 CRUD** | 景点/美食/路线落库 + 查询接口 + 种子数据 | 前端列表/详情可读 |
| **M4 收藏打卡** | 收藏增删查 + 打卡 + OSS 直传签名 | 前端收藏/打卡同步云端 |
| **M5 打磨** | 分页/搜索/Redis 缓存 + 单元测试 + README | 测试通过、文档齐全 |

> P2(评论/图墙/游记)与 P3(推荐/足迹统计/运营后台)在 P1 验收后另行排期。

## 7. 环境要求

- Go ≥ 1.22,MySQL 8.x,Redis ≥ 6.x
- `.env` 需配置:`DB_HOST/DB_PORT/DB_USER/DB_PASS/DB_NAME`、`REDIS_ADDR`、`JWT_SECRET`、`OSS_*`
- 本地编辑器 > `d:\桌面\文旅\houduan` 打开即可
